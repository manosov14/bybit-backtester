# Стратегия ложных пробоев

Написать бот для торговли ложных пробоев на рынке бессрочных фьючерсов крипто биржи Bybit.

## 1) Цель и общая идея

Торгуем простые ложные пробои дневных уровней на рынке бессрочных фьючерсов Bybit. Базовые инструменты задаются пользователем.

Управление ботом — через консоль или телеграмм.

Базовые параметры стратегии, режимы и лимиты должны быть настраиваемыми.

## 2) Условия работы

- Площадка: Bybit Perpetuals, 20 самых ликвидных пар (задаются в Env файле).
- Запуск: домашний компьютер/сервер.

Бот должен поддерживать:

1. Определение трендов D1 и H4.
2. Определение рабочих дневных уровней – экстремумов предыдущих уровней.
3. Фильтрацию сигналов пробоя.
4. Сканирование сигналов пробоя в реальном времени.
5. Реальную торговлю.
6. Тестирование на истории.

### Фильтры

1. Фильтр D1 и H4 тренда.
2. Фильтр сессий.
3. Фильтр глубины прокола.
4. Фильтр скорости подхода к уровню.
5. Фильтр Дельты объёма (по умолчанию не используется).

Каждый фильтр должен отдельно включаться и выключаться.

## 3) Фильтр Определение тренда (отдельный модуль)

- H4: тренд по SMA(50).
- D1: тренд по SMA(200).

Значения SMA должны быть настраиваемыми.

Оба фильтра имеют флаги, которые определяют возможность торговли в данном направлении.

Если фильтр H4 отключён, торговля по тренду H4 не выполняется.

В соответствии с настройкой H4 торгуются вручную заданные H4-уровни, а в соответствии с настройкой D1 — D1-уровни экстремумов предыдущих дней.

Эта логика действует даже в случае разнонаправленности D1 и H4 трендов.

## 4) Модуль определения уровней для торговли (экстремумы N предыдущих дней)

Из диапазона последних N дней отбираются экстремумы дневных свечей, по которым за эти N дней не снималась ликвидность.

Для лонгового дневного тренда берём минимумы, для шортового — максимумы.

Определяем внутренние дни (дневная свеча уровня находится в диапазоне предыдущих N свечей – является настраиваемым параметром).

Участие внутренних дней в определении уровней для торговли должно быть настраиваемым.

### 4.1 Модуль фильтра торгового времени

(Us, EU) – определяет торговые сессии для работы бота.

## 5.1 Модуль фильтра скорости подхода

### Базовая формула

```text
SpeedRatio = ΔЦена / ATR
```

где:

```text
ΔЦена = разница между ценой начала импульса и текущей ценой (или уровнем)
ATR = текущее значение ATR(14) на H1
```

### Практическое применение SpeedRatio

| SpeedRatio (ΔЦена / ATR) | Интерпретация | Скорость подхода |
|---|---|---|
| < 1.0 | Медленно, «ползком» | Низкая |
| 1,0–1,5 | Умеренно | Средняя |
| > 1,5–2,0 | Быстрое движение | Высокая скорость |
| > 2,5–3,0 | Импульс/паника | Очень высокая скорость, возможен ложный пробой |

### Пример

Предположим:

- ATR(14) H1 = 40 пунктов
- Цена выросла с 1,1000 до 1,1080 (`ΔPrice = 80 пунктов`)
- Время в пути — 2 часа

```text
SpeedRatio=80/40=2.0
SpeedRatio = 80 / 40 = 2.0
SpeedRatio=80/40=2.0
```

👉 Цена прошла 2 ATR за 2 свечи — высокая скорость движения.

Если бы это же движение заняло 6 часов, соотношение было бы ≈ 0,67:

```text
80 / (40 × 3)
```

→ вялый подход, рынок переваривает.

## 6) Модуль фильтра глубины прокола и дельты объёма

Параметры минимального и максимального прокола задаются в файле env базово:

```text
0,1 – 0,35 ATR H1(14)
```

## 7) Риск и мани менеджмент

- Риск на сделку: по умолчанию 1% капитала.
- Стоп серия: при 3 стоп лоссах подряд бот приостанавливает торговлю.
- Одновременно не более 2 сделок одновременно.

## 8) Живой режим и защита от повторных входов

Поддерживаются два режима команды `/Run`:

- тестовый (без реальных ордеров),
- боевой (реальная торговля с выставлением ордеров на Bybit).

## 9) Команды админа

### `/param`

Вывести текущие значения всех настроек и используемых стратегией параметров из настроек стратегии.

### `/days N`

Модуль анализа на истории, анализ последних N дней по ложным пробоям (фильтр по тренду D1, при шорте оцениваются только максимум проколы, при лонге — минимум проколы).

Для каждого кейса вывести:

- дата и время ложного пробоя;
- направление тренда D1 и H4 на момент сигнала;
- % пробития уровня;
- был ли возврат (да/нет);
- уровень входа;
- уровень стоп лосса;
- уровень тейк профита;
- результат (стоп или профит);
- причина отказа от сделки (если сигнал отфильтрован).

### `/levels`

В табличном виде выдать рабочие уровни для каждого инструмента из списка, исходя из параметра N (сколько дней берём для определения уровней).

Плюс вывести информацию о всех уровнях H4, поместив их в раздел `manual`.

### `/run`

Запустить сканирование и обработку сигналов ложных пробоев в реальном времени.

Режим работы выбирается пользователем:

- в тестовом режиме — детектируем и печатаем следующую информацию: пробой, возврат, фильтры и причины фильтрации или сигнал о входе;
- в боевом — дополнительно выставляем стоп ордера на вход при возврате за уровень пробоя, стоп лосс ставим за уровень прокола (по умолчанию) или за N тиков за пробитый уровень (является настраиваемым параметром).

### `/trend`

Выводит значения D1,H4 трендов по всем парам и состояние флагов D1 и H4.

### `/Quit`

Заканчивает работу бота.

## Алгоритм стратегии

При запуске бота, он вычисляет все уровни для наших торговых инструментов (дневные экстремумы предыдущих дней в заданном временном окне, изломы дневного тренда на истории).

При переходе на другой день, он заново пересчитывает уровни.

Также мы вычисляем D1 и H4 тренды по нашим парам.

Команды `/param`, `/trend`, `/levels` показывают нам все параметры из настроек стратегии, тренды по нашим парам, и вычисленные уровни.

При запуске команды `/run` запускается сканирование (ожидание) ложных пробоев.

При приближении цены к уровню на расстояние ATR (5М) сканирование нужно перевести на 1М тайм фрейм, чтобы не пропустить резкие проколы и уход в диапазон.

При попадании цены в минимально допустимый диапазон прокола (является настраиваемым параметром и по умолчанию `0.1 ATR H1(14)`) сканер даёт команду ордер менеджеру выставить стоп ордер на вход в сделку и устанавливает стоп и профит ордера.

Вход в этой стратегии осуществляется по рынку bye stop или sell stop ордерами при заходе обратно за уровень.

Если прокол пойдёт дальше и превысит максимально допустимое значение, то стоп заявка на вход в сделку снимается.

В случае проскальзывания цены через стоп заявку, она снимается через 5 минут.

Допустимое время возврата – N пятиминутных свечей (по умолчанию 2).

Т.е. если за это время не произошёл возврат к уровню, то стоп ордер на вход в сделку снимается вместе со стоп лоссом и тейк профитом.

Уровень, где выставляется заявка – несколько (N-является настраиваемым параметром) тиков (по умолчанию 2 тика) за уровнем пробоя со стороны пробоя (стоп заявка срабатывает после возврата цены за уровень на 2 тика).

Стоп ордер по умолчанию выставляется за уровень прокола или несколько тиков (M тиков) за пробитый уровень (это устанавливается флагом-переключателем в env файле).

При установке стоп ордера на вход в сделку нам не известна глубина прокола, поэтому изначально стоп лосс ставим за максимально допустимый прокол фильтра глубины прокола, а при входе в сделку стоп лосс переносим за реальный прокол.

Тейк профит задаётся с соотношением RR (по умолчанию 3) — является настраиваемым параметром.

Торговля возможна и по H4 и по D1 трендам в соответствии с настройками стратегии.

Если тренды разнонаправленные, D1 уровни торгуются по тренду D1, H4 уровни (введённые вручную) торгуются в любом направлении не зависимо от флага H4.

В случае проскальзывания и не срабатывании стоп заявок, они снимаются, а в случае не срабатывания стоп лосса или тейк профита, сделки закрываются по рынку немедленно.

Одновременно возможно не более 1 сделки.

# MVP

## Цель MVP

Цель MVP — проверить работоспособность стратегии ложного пробоя на реальных исторических данных Bybit для одной торговой пары:

```text
BTCUSDT
```

MVP предназначен только для проверки того, что правила стратегии можно однозначно воспроизвести на исторических данных и получить понятный результат.

## В MVP входит

### 1. Торговый инструмент

Используется только:

```text
BTCUSDT
```

Рынок:

```text
Bybit Perpetuals
```

Другие торговые пары в MVP не входят.

### 2. Единственная стратегия

В MVP входит только:

```text
False Breakout
```

Другие торговые стратегии не входят в первую версию.

### 3. Определение D1-тренда

Для BTCUSDT определяется дневной тренд по:

```text
SMA(200)
```

В зависимости от направления тренда:

- при LONG рассматриваются ложные пробои минимумов;
- при SHORT рассматриваются ложные пробои максимумов.

### 4. Рабочие дневные уровни

Рабочие уровни определяются по экстремумам предыдущих N дневных свечей.

Используются уровни, по которым за рассматриваемый период не была снята ликвидность.

Количество анализируемых дней N должно быть настраиваемым.

Участие внутренних дней также должно быть настраиваемым.

### 5. Поиск ложного пробоя

Для каждого рабочего уровня необходимо определить:

- произошёл ли пробой;
- глубину прокола;
- произошёл ли возврат за уровень;
- уложился ли возврат в допустимое время;
- является ли сигнал допустимым для сделки.

### 6. Фильтр глубины прокола

Используется минимальная и максимальная допустимая глубина прокола.

Базовый диапазон:

```text
0.1 – 0.35 ATR H1(14)
```

Если глубина прокола меньше минимальной или больше максимальной, сигнал отклоняется.

### 7. Фильтр скорости подхода

Используется оценка скорости подхода цены к уровню.

Базовая формула:

```text
SpeedRatio = ΔPrice / ATR
```

где ATR рассчитывается на H1.

Фильтр должен позволять отличать медленный подход от быстрого импульсного движения.

### 8. Возврат за уровень

После пробоя цена должна вернуться обратно за рабочий уровень в течение ограниченного времени.

Базовое значение:

```text
2 свечи M5
```

Если возврата за это время нет, сигнал считается недействительным.

### 9. Entry

После подтверждённого возврата рассчитывается цена входа.

Базовый отступ:

```text
2 тика от рабочего уровня
```

В рамках MVP реальная заявка не выставляется.

### 10. Stop Loss

Stop Loss рассчитывается за фактический экстремум прокола.

### 11. Take Profit

Take Profit рассчитывается по фиксированному Risk/Reward.

Базовое значение:

```text
RR = 3
```

### 12. Историческая проверка

Пользователь должен иметь возможность запустить анализ BTCUSDT за последние N дней.

Для каждого найденного ложного пробоя необходимо показать:

- дату и время;
- направление D1-тренда;
- рабочий уровень;
- глубину пробоя;
- скорость подхода;
- факт возврата;
- Entry;
- Stop Loss;
- Take Profit;
- результат;
- причину отказа, если сигнал был отфильтрован.

### 13. Результат сделки

Для каждого принятого сигнала необходимо определить:

- Entry;
- Stop Loss;
- Take Profit;
- результат сделки;
- Stop Loss или Take Profit;
- достигнутый RR.

### 14. Итоговая статистика

По выбранному периоду необходимо рассчитывать:

- number of trades;
- profitable trades;
- losing trades;
- win rate;
- Profit Factor;
- average reward-to-risk;
- maximum drawdown;
- final result.

### 15. Объяснимость

Для каждого потенциального сигнала должно быть понятно:

- почему сигнал принят;
- почему сигнал отклонён;
- какой фильтр стал причиной отказа;
- почему сетап перестал быть актуальным;
- чем завершилась смоделированная сделка.

# Что не входит в MVP

В первую версию не входят:

- любые другие стратегии кроме False Breakout;
- торговые пары кроме BTCUSDT;
- автоматический выбор наиболее ликвидных инструментов;
- реальные торговые ордера;
- live trading;
- ручные H4-уровни;
- торговля по H4-тренду;
- фильтр дельты объёма;
- несколько одновременно открытых сделок;
- расширенный money management;
- дневной лимит риска;
- stop-series protection;
- сложный realtime focus mode;
- сопровождение реальных заявок;
- обработка проскальзывания;
- аварийное закрытие реальных позиций;
- web interface;
- charts;
- machine learning;
- автоматическая оптимизация стратегии.

---

# Критерий успеха MVP

MVP считается успешным, если пользователь может запустить исторический анализ стратегии False Breakout для `BTCUSDT` за выбранный период и получить:

1. найденные потенциальные ложные пробои;
2. результат применения фильтров;
3. рассчитанные Entry, Stop Loss и Take Profit;
4. результат каждой смоделированной сделки;
5. причину отказа для каждого отклонённого сигнала;
6. итоговую статистику стратегии.

Главная цель первой версии — подтвердить, что стратегия ложного пробоя формализована однозначно и воспроизводимо работает на исторических данных BTCUSDT.
